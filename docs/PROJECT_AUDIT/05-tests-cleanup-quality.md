# Этап 5. Тесты, cleanup и технический долг

## Цель

Закрыть пробелы в тестах, убрать технический шум и сделать проект устойчивым к регрессиям. Этот этап нужен после критических исправлений, чтобы ошибки не возвращались при следующих доработках.

## Основные проблемы из аудита

- Несколько backend-приложений почти не покрыты тестами.
- Нет достаточных тестов на WebSocket, race conditions и unread.
- Есть много молчаливых обработчиков ошибок.
- В production-коде есть debug print и console log.
- Есть пустые CSS-заглушки.
- Есть устаревшие документы и неактуальные инструкции.
- Есть дубли и мертвые сущности.

## Задачи

### Backend-тесты

- Добавить тесты для knowledge: вопросы, ответы, статьи, жалобы и оспаривания.
- Добавить тесты для payments: создание платежа, callback, sandbox, идемпотентность.
- Добавить тесты для admin panel: обращения, сообщения, теги, статусы, логирование.
- Добавить тесты для notifications: создание, дедупликация, action-кнопки, отправка.
- Добавить тесты для wallet: пополнение, вывод, резерв, возврат, история операций.
- Добавить тесты для partner: рефералы, начисления, кошелек партнера.

### Тесты чатов

- Добавить consumer-тесты WebSocket.
- Проверить отправку и получение сообщений.
- Проверить unread и mark as read.
- Проверить чат после блокировки и разблокировки.
- Проверить основной чат и чаты заказов между одними пользователями.
- Проверить отправку файлов.

### Тесты конкурентности

- Проверить параллельное принятие заказа.
- Проверить параллельное принятие индивидуального предложения.
- Проверить параллельное завершение заказа.
- Проверить повторный callback оплаты.
- Проверить повторное создание заявки на вывод.

### Playwright E2E

- Добавить сценарии для арбитратора.
- Добавить сценарии для администратора.
- Добавить сценарии для полного заказа клиентом и экспертом.
- Добавить сценарии для блокировки за контакты.
- Добавить сценарии для жалоб на отзыв, статью, вопрос и заказ.
- Добавить сценарии для партнерского кабинета и кошелька.

### Cleanup ошибок и логирования

- Заменить молчаливое проглатывание ошибок на явное логирование.
- Убрать debug print из production API.
- Убрать лишние frontend console log.
- Скрывать технические ошибки от пользователя, но сохранять диагностику для разработчика.
- Проверить, что ошибки API показываются понятным текстом.

### Cleanup структуры

- Проверить и удалить неиспользуемые endpoint.
- Проверить пустые приложения и views.
- Проверить дубли serializers.
- Проверить устаревшие enum и legacy actions.
- Проверить пустые CSS-файлы и заглушки.
- Обновить документацию по запуску, платежам и ручному QA.

## Критерии готовности

- Критичные финансовые сценарии покрыты backend-тестами.
- Чаты покрыты тестами на отправку, unread и блокировку.
- Нет debug print с чувствительными данными.
- Нет молчаливого проглатывания критичных ошибок.
- Неактуальные API и документы либо удалены, либо помечены как legacy.
- Playwright покрывает основные пользовательские роли.

## Проверки

- Запустить полный backend test suite.
- Запустить frontend build и typecheck.
- Запустить Playwright API и browser tests.
- Проверить отсутствие новых console errors в браузере.
- Проверить логи backend на отсутствие чувствительных данных.
- Проверить документацию запуска и ручного тестирования.

## Риски после этапа

Добавление тестов может вскрыть старые скрытые дефекты, которые раньше не проявлялись. Это нормально: этап нужно планировать с запасом на исправление найденных регрессий.
