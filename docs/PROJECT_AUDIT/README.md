# Проектный аудит OkoZnaniy

Эта папка разбивает общий аудит проекта на отдельные этапы работ. Исходный документ: `docs/PROJECT_AUDIT.md`.

Цель разбиения: превратить общий список рисков, багов и пробелов в тестах в управляемый план, где каждый этап можно брать в работу отдельно, проверять по критериям готовности и закрывать без смешивания разных областей.

## Приоритеты

1. **Сначала деньги, заказы и доступы.** Любые ошибки в списании, заморозке, возврате, начислениях и правах доступа могут привести к потере денег или некорректному состоянию заказа.
2. **Затем чаты, unread, WebSocket и арбитраж.** Эти сценарии напрямую влияют на коммуникацию клиента, эксперта, администратора и директора.
3. **После этого админка и API-состыковка.** Администратор должен видеть и регулировать платформу без 404, неактуальных endpoint и обходов прав.
4. **Потом UI, адаптив и темная тема.** Интерфейс должен быть читаемым и управляемым на мобильных, desktop и в темной теме.
5. **Финально тесты, cleanup и регрессионная защита.** После исправлений нужно закрыть пробелы тестами и убрать шум, который маскирует настоящие ошибки.

## Как работать с этапами

Каждый этап содержит:

- цель;
- список задач;
- риски, которые закрывает этап;
- критерии готовности;
- минимальный набор проверок;
- ручные сценарии, которые нужно пройти после реализации.

Этап считается закрытым только если выполнены задачи, пройдены проверки и нет новых регрессий в связанных пользовательских сценариях.
