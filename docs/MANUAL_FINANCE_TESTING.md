# Руководство по ручному тестированию финансов

**Цель:** Пошаговые процедуры проверки всех 22 исправлений аудита в режиме sandbox/emulator.
**Предусловия:** Бэкенд запущен на `localhost:8000`, доступна учётная запись staff, `PAYMENTS_SANDBOX=True`.

---

## Тестовое окружение

- **URL:** `http://localhost:8000/api/v1/`
- **Staff-пользователь:** любая почта `@okoznaniy.test` или пользователь с is_staff=True
- **Sandbox-режим:** все платежи мгновенные, реальный банк не нужен

---

## P0 — Критичные исправления

### Тест #1: cancel_overdue возвращает замороженные средства
1. Создайте заказ с бюджетом 5000 ₽ → баланс уменьшается на 5000, frozen_balance увеличивается на 5000
2. Закажите заказ (средства остаются замороженными)
3. Установите дедлайн заказа вручную в прошлое (или подождите)
4. Выполните команду: `python manage.py cancel_overdue`
5. **Проверка:** frozen_balance = 0, баланс восстановлен на 5000
6. Проверьте модель Transaction: HOLD отменён, есть новая запись CREDIT

### Тест #2: Нельзя удалить завершённый заказ с транзакциями
1. Создайте заказ → завершите его → убедитесь, что есть записи Transaction
2. Попробуйте удалить через API: `DELETE /api/v1/orders/{id}/`
3. **Проверка:** Ответ HTTP 409, заказ на месте
4. Попробуйте удалить незавершённый заказ → должен удалиться

### Тест #3: Проверка подписи callback платежей
1. Отправьте callback на `/api/v1/payments/callback/alfa/` с неверным orderId
2. **Проверка:** Ответ 403/400 (отклонение подписи)
3. Отправьте callback на `/api/v1/payments/callback/sbp/` с неверным HMAC
4. **Проверка:** Ответ 403/400
5. Только корректно подписанные callback'и должны обрабатываться

## P1 — Высокие исправления

### Тест #4: Финансовая панель директора использует реальные данные
1. Войдите как директор/админ
2. Откройте финансовую панель: `GET /api/v1/director/finance/net-profit/`
3. **Проверка:** Ответ содержит реальные данные транзакций COMMISSION/PAYOUT, НЕ захардкоженные 70%
4. total_income, total_expenses и net_profit должны совпадать с записями в БД

### Тест #5: Комиссия партнёра в панели
1. Создайте партнёрскую реферальную связь
2. Завершите заказ, генерирующий партнёрскую комиссию
3. Проверьте раздел partner_earnings финансовой панели
4. **Проверка:** Суммы PartnerEarning отображаются в ответе панели

### Тест #6: Предупреждение при отсутствии ключа PaymentCrypto
1. Уберите `PAYMENT_ENCRYPTION_KEY` из переменных окружения
2. Инициируйте криптоплатёжную операцию
3. **Проверка:** В логе появляется предупреждение (не молчаливая ошибка, не перегенерация ключа)

### Тест #7: Защита от гонки при пополнении
1. Отправьте 10 одновременных запросов на пополнение на одну сумму
2. **Проверка:** Только 1 пополнение успешное, остальные отклонены или дедуплицированы
3. Проверьте баланс: увеличен только один раз

## P2 — Средние исправления

### Тест #8: Минимальный бюджет заказа
1. Попробуйте создать заказ с бюджетом = 0 → **Проверка:** 400 Bad Request
2. Попробуйте создать заказ с бюджетом = -100 → **Проверка:** 400 Bad Request
3. Создайте заказ с бюджетом = 0.01 → **Проверка:** Успешно

### Тест #9: Скидка ограничена 100%
1. Создайте заказ с бюджетом 1000 ₽
2. Попробуйте применить скидку > 100% (например, discount_amount = 1500)
3. **Проверка:** final_price = 0 (ограничено), не -500

### Тест #10: Скидка не перезаписывает бюджет
1. Создайте заказ с бюджетом 5000 ₽
2. Примените скидку 20% (discount_amount = 1000)
3. **Проверка:** бюджет остаётся 5000, final_price = 4000
4. Бюджет НЕ должен измениться на 4000

### Тест #11: take_order делегирует в Order.take()
1. Создайте заказ → возьмите его
2. **Проверка:** Статус заказа меняется на "taken", установлен фрилансер
3. Оба эндпоинта (deprecated и новый) должны работать одинаково

### Тест #12: Покупка в магазине через эскроу
1. Купите товар в магазине
2. **Проверка:** Платёж проходит через цепочку `hold` → `release_to_expert`
3. Проверьте модель Transaction на наличие записей HOLD + RELEASE (не direct_transfer)
4. Баланс эксперта зачисляется только после завершения заказа

### Тест #13: Пополнения видны в списке платежей
1. Создайте платёж пополнения
2. Запросите: `GET /api/v1/payments/`
3. **Проверка:** Платёж пополнения отображается в списке (не только платежи по заказам)

### Тест #14: Ограничение частоты запросов к кошельку
1. Отправьте 31 быстрый запрос к эндпоинтам кошелька
2. **Проверка:** Запрос #31 возвращает 429 Too Many Requests
3. Подождите 1 минуту, повторите → должен выполниться

### Тест #15: Лимиты вывода средств
1. Попробуйте вывести 50 ₽ → **Проверка:** Отклонено (ниже мин. 100)
2. Попробуйте вывести 600 000 ₽ → **Проверка:** Отклонено (выше макс. 500 000)
3. Выведите 100 ₽ → **Проверка:** Успешно
4. Выведите 500 000 ₽ → **Проверка:** Успешно (если баланс достаточен)
5. Несколько выводов на общую сумму > 1 000 000 за день → **Проверка:** Дневной лимит соблюдён

## P3 — Низкие исправления

### Тест #16: get_stats корректно считает RELEASE
1. Завершите заказ (генерирует транзакцию RELEASE)
2. Проверьте статистику кошелька: `GET /api/v1/wallet/stats/`
3. **Проверка:** total_spent включает суммы RELEASE, а не HOLD

### Тест #17: accept_bid обновляет бюджет
1. Создайте заказ с бюджетом 3000
2. Эксперт предлагает 2500
3. Примите заявку
4. **Проверка:** Бюджет заказа теперь 2500 (равен сумме заявки)

### Тест #19: Идемпотентность пополнения
1. Создайте платёж пополнения (не оплачивайте)
2. Попробуйте создать ещё одно пополнение на ту же сумму
3. **Проверка:** Возвращается существующий ожидающий платёж, а не новый
4. Проверка: в БД только 1 запись Payment

### Тест #20: Ограничения баланса в БД
1. Попробуйте вручную установить User.balance = -1 в БД
2. **Проверка:** БД отклоняет с нарушением CheckConstraint
3. То же самое для frozen_balance = -1

### Тест #21: Округление PartnerEarning
1. Создайте партнёрский заработок с суммой > 2 знаков (например, 123.456)
2. **Проверка:** Сохранённое значение — 123.46 (округлено до 2 знаков)

### Тест #22: Валидация дедлайна заказа
1. Попробуйте создать заказ с дедлайном в прошлом
2. **Проверка:** Выброшена ValidationError, заказ не создан
3. Создайте заказ с дедлайном в будущем → **Проверка:** Успешно


## Примечания

- Все тесты выполняются в sandbox-режиме — реальные деньги не задействованы

- Мониторинг логов бэкенда: `docker compose logs -f backend`
