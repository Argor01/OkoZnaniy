# Руководство по ручному тестированию финансов

**Цель:** Проверка всех финансовых исправлений аудита через сценарии тестирования.
**Предусловия:** Бэкенд запущен на `localhost:8000`, учётная запись staff, `PAYMENTS_SANDBOX=True`.

---

## Тестовое окружение

- **URL:** `http://localhost:8000/api/v1/`
- **Staff-пользователь:** почта `@okoznaniy.test` или пользователь с `is_staff=True`
- **Sandbox-режим:** все платежи мгновенные, реальный банк не нужен

---

## 1. Отмена просроченных заказов

### Позитивный сценарий — средства возвращаются на баланс

1. Создайте заказ с бюджетом 5000 ₽
2. Убедитесь: баланс уменьшился на 5000, `frozen_balance` увеличился на 5000
3. Закажите заказ (средства остаются замороженными)
4. Установите дедлайн заказа в прошлое
5. Выполните: `python manage.py cancel_overdue`
6. **Ожидаемый результат:** `frozen_balance = 0`, баланс восстановлен на 5000
7. Проверьте модель `Transaction`:_HOLD отменён, есть новая запись `CREDIT`

### Негативный сценарий — заказ без просрочки не отменяется

1. Создайте заказ с бюджетом 3000 ₽
2. Установите дедлайн на неделю вперёд
3. Выполните: `python manage.py cancel_overdue`
4. **Ожидаемый результат:** заказ остался в прежнем статусе, баланс не изменился

---

## 2. Удаление завершённого заказа

### Позитивный сценарий — незавершённый заказ удаляется

1. Создайте заказ
2. Убедитесь, что заказ не завершён и нет финансовых транзакций
3. Отправьте: `DELETE /api/v1/orders/{id}/`
4. **Ожидаемый результат:** HTTP 204, заказ удалён

### Негативный сценарий — завершённый заказ с транзакциями не удаляется

1. Создайте заказ → завершите его
2. Убедитесь, что есть записи `Transaction`
3. Отправьте: `DELETE /api/v1/orders/{id}/`
4. **Ожидаемый результат:** HTTP 409, заказ на месте

---

## 3. Проверка подписи callback платежей

### Позитивный сценарий — корректная подпись обрабатывается

1. Подпишите callback валидным HMAC
2. Отправьте на `/api/v1/payments/callback/alfa/`
3. **Ожидаемый результат:** HTTP 200, платёж обработан

### Негативный сценарий — неверная подпись отклоняется

1. Отправьте callback на `/api/v1/payments/callback/alfa/` с неверным `orderId`
2. **Ожидаемый результат:** HTTP 403 или 400
3. Отправьте callback на `/api/v1/payments/callback/sbp/` с неверным HMAC
4. **Ожидаемый результат:** HTTP 403 или 400

## 4. Финансовая панель директора

### Позитивный сценарий — данные реальные, не захардкоженные

1. Войдите как директор/админ
2. Откройте: `GET /api/v1/director/finance/net-profit/`
3. **Ожидаемый результат:** ответ содержит реальные данные транзакций `COMMISSION`/`PAYOUT`
4. `total_income`, `total_expenses` и `net_profit` совпадают с записями в БД

### Негативный сценарий — без транзакций показывает нули

1. Создайте нового пользователя без истории транзакций
2. Откройте финансовую панель
3. **Ожидаемый результат:** все суммы равны 0, нет захардкоженных значений

---

## 5. Партнёрская комиссия в панели

### Позитивный сценарий — комиссия отображается

1. Создайте партнёрскую реферальную связь
2. Завершите заказ, генерирующий партнёрскую комиссию
3. Проверьте раздел `partner_earnings` финансовой панели
4. **Ожидаемый результат:** суммы `PartnerEarning` отображаются в ответе панели

### Негативный сценарий — без привязки партнёра комиссии нет

1. Создайте заказ без партнёрской привязки
2. Завершите его
3. **Ожидаемый результат:** в `partner_earnings` пустой список или сумма 0

## 6. Предупреждение при отсутствии ключа шифрования

### Позитивный сценарий — ключ есть, предупреждений нет

1. Убедитесь, что `PAYMENT_ENCRYPTION_KEY` задан в переменных окружения
2. Выполните криптоплатёжную операцию
3. **Ожидаемый результат:** операция проходит без предупреждений в логе

### Негативный сценарий — ключ отсутствует, появляется предупреждение

1. Уберите `PAYMENT_ENCRYPTION_KEY` из переменных окружения
2. Инициируйте криптоплатёжную операцию
3. **Ожидаемый результат:** в логе появляется предупреждение (не молчаливая ошибка)

## 7. Защита от гонки при пополнении

### Позитивный сценарий — одиночное пополнение работает

1. Отправьте 1 запрос на пополнение на сумму 1000 ₽
2. **Ожидаемый результат:** пополнение успешно, баланс increased на 1000

### Негативный сценарий — одновременные пополнения не дублируются

1. Отправьте 10 одновременных запросов на пополнение на 1000 ₽
2. **Ожидаемый результат:** только 1 пополнение успешное, остальные отклонены или дедуплицированы
3. Проверьте баланс: увеличен только на 1000, а не на 10 000

## 12. Покупка в магазине через эскроу
