# Сквозная проверка финансов

Документ фиксирует, как проверять финансовую связку между заказами, кошельком,
админкой, директорским кабинетом и партнерским кабинетом.

## Цель

Проверить, что деньги не живут отдельно от пользовательских сценариев:

- клиент пополняет кошелек и оплачивает заказ;
- деньги резервируются на заказе;
- эксперт получает выплату после принятия работы;
- клиент получает возврат при отклонении работы;
- готовая работа покупается через кошелек и создает заказ;
- партнер получает начисление за реферала и заказ реферала;
- админ видит партнерские начисления и может отметить их выплаченными;
- директор видит партнерский оборот и финансовую статистику.

## Карта ролей и модулей

| Роль | Что проверяем | Основные API |
| --- | --- | --- |
| Клиент | Баланс, пополнение, резерв заказа, возврат, покупка готовой работы | `/api/wallet/*`, `/api/payments/*`, `/api/orders/orders/*`, `/api/shop/works/*` |
| Эксперт | Получение выплаты за заказ или готовую работу | `/api/orders/orders/*`, `/api/wallet/me/` |
| Администратор | Партнерские начисления, отметка выплаты, модерация готовых работ | `/api/users/admin_earnings/`, `/api/users/admin_mark_earning_paid/`, `/api/admin-panel/works/*` |
| Директор | Оборот, чистая прибыль, партнерский оборот, сводка | `/api/director/finance/*`, `/api/director/partners/*`, `/api/director/statistics/*` |
| Партнер | Реферальный код, рефералы, последние начисления | `/api/users/partner_dashboard/`, `/api/users/generate_referral_link/` |

## Проверенные сценарии

### Пополнение кошелька в санбоксе

Предусловия:

- `PAYMENTS_SANDBOX=True`.
- Пользователь является сотрудником или имеет email на `@okoznaniy.test`.

Ожидаемый результат:

- API возвращает успешный платеж с признаком `sandbox`.
- Создается одна транзакция `topup`.
- Повторное сохранение завершенного платежа не дублирует начисление.

Автотест: `WalletSandboxTests.test_sandbox_topup_credits_test_wallet_once`.

### Вывод средств

Предусловия:

- У пользователя есть доступный баланс.
- Номер карты проходит простую валидацию.

Ожидаемый результат:

- Баланс уменьшается сразу.
- Создается транзакция `withdrawal`.
- Создается заявка `WithdrawalRequest(status=pending)`.

Автотест: `WalletSandboxTests.test_withdraw_debits_wallet_and_creates_pending_request`.

### Принятие работы клиентом

Предусловия:

- Заказ находится в статусе `review`.
- По заказу есть активный резерв `hold`.

Ожидаемый результат:

- Заказ переходит в `completed`.
- У клиента списывается сумма резерва.
- У клиента снимается `frozen_balance`.
- Эксперт получает выплату за вычетом комиссии.
- Системный аккаунт `_system_commission` получает комиссию.

Автотест: `WalletOrderLedgerTests.test_approve_releases_order_hold_to_expert_with_commission`.

### Отклонение работы клиентом

Предусловия:

- Заказ находится в статусе `review`.
- По заказу есть активный резерв `hold`.

Ожидаемый результат:

- Заказ переходит в `cancelled`.
- Резерв снимается.
- Доступный баланс клиента восстанавливается.
- Эксперт не получает выплату.

Автотест: `WalletOrderLedgerTests.test_reject_refunds_order_hold_to_available_balance`.

### Внешний callback оплаты заказа

Предусловия:

- Есть `Payment(status=pending)`, связанный с заказом в `waiting_payment`.

Ожидаемый результат:

- Платеж становится `completed`.
- Создается `topup`.
- Создается `hold` по заказу.
- Заказ переходит в `in_progress`.
- Повтор callback не создает повторных транзакций.

Автотест: `WalletOrderLedgerTests.test_external_order_payment_callback_creates_idempotent_wallet_hold`.

### Покупка готовой работы

Предусловия:

- Готовая работа активна и одобрена модерацией.
- Покупатель не является автором.
- У покупателя достаточно средств.

Ожидаемый результат:

- Деньги списываются с покупателя.
- Автор получает выплату за вычетом комиссии.
- Платформа получает комиссию.
- Создается заказ в `in_progress`.
- Покупка и транзакции связаны с этим заказом.

Автотест: `ReadyWorkPurchaseWalletTests.test_purchase_debits_buyer_pays_author_and_creates_order`.

Негативный сценарий:

- Если средств недостаточно, API возвращает `400`, покупка, заказ и транзакции не создаются.

Автотест: `ReadyWorkPurchaseWalletTests.test_purchase_requires_available_wallet_funds`.

### Партнерское начисление за заказ реферала

Предусловия:

- Клиент зарегистрирован с `partner`.
- Заказ клиента завершен.

Ожидаемый результат:

- Создается `PartnerEarning` с типом `order`.
- Сумма начисления считается от бюджета заказа и `partner_commission_rate`.
- Партнерский кабинет видит сумму в `partner_dashboard`.
- Директорский раздел партнеров видит оборот и комиссию.
- Админский endpoint начислений видит запись.
- Админ может отметить начисление выплаченным.

Автотест: `WalletOrderLedgerTests.test_completed_referred_order_is_visible_in_partner_and_director_finance`.

### Партнерский бонус за регистрацию

Предусловия:

- Есть активный пользователь с ролью `partner`.
- У партнера есть `referral_code`.
- Новый клиент регистрируется с этим реферальным кодом.

Ожидаемый результат:

- У нового клиента сохраняется связь `partner`.
- Создается `PartnerEarning` с типом `registration`.
- Партнер получает регистрационный бонус 50 ₽.
- У партнера обновляются `total_referrals` и `total_earnings`.

Автотест: `PartnerReferralFinanceTests.test_registration_with_referral_code_creates_partner_bonus`.

## Найденные и исправленные проблемы

- Директорские финансовые отчеты парсили `start_date`/`end_date` как naive datetime при включенном timezone. Добавлен единый `parse_aware_date_range`, который строит границы дня в текущем timezone.
- Документ `WALLET_PAYMENT_QA.md` был на английском. Переведен на русский.
- Добавлен автотест, который связывает завершение заказа, партнерское начисление, партнерский кабинет, директорский оборот и админскую отметку выплаты.
- Добавлен автотест регистрационного бонуса партнера по реферальному коду.

## Оставшиеся ограничения

- Реальный эквайринг и реальные банковские выплаты пока не подключены, поэтому проверяются только санбокс и внутренний финансовый журнал.
- Подтверждение заявки на вывод есть в Django admin, но отдельного API/экрана для финансового оператора пока нет.
- В старых backend-файлах еще встречаются русские строки с битой кодировкой. Это не блокирует финансовые сценарии, но может давать нечитаемые системные тексты.
